# Contribuindo com o Proviziona

Obrigado por considerar uma contribuição.

O projeto ainda está em fase inicial. Para evitar trabalho duplicado, abra uma issue antes de mudanças grandes, novas dependências ou alterações de arquitetura.

## Fluxo recomendado

1. Procure uma issue existente ou crie uma descrevendo o problema.
2. Faça um fork e crie uma branch curta e focada.
3. Implemente a mudança com testes quando aplicável.
4. Atualize a documentação afetada.
5. Abra um pull request explicando o problema, a solução e como validar.

Commits no formato `tipo: descrição` são recomendados, por exemplo:

```text
feat: add provisioning cycle
fix: prevent duplicate sync movement
docs: explain self-host setup
```

## Critérios básicos

- mantenha cada pull request focado em um único objetivo;
- não inclua segredos, dados pessoais ou arquivos gerados;
- preserve o funcionamento offline e o caminho de self-host;
- evite dependências sem necessidade clara;
- trate as outras pessoas com respeito e discuta ideias, não indivíduos.

## Licença

Ao enviar uma contribuição, você concorda que ela será distribuída sob a licença AGPL-3.0 do projeto.

Não há CLA ou processo burocrático adicional neste momento.
